# doc (Word 97 to 2003)

The binary Word format, defined in Microsoft's [MS-DOC] specification (publicly available). The parser follows [MS-DOC] for every structure named here; field names below are the specification's, so they can be looked up there. Offsets inside the FIB vary by version and must be read from the specification, never guessed. The `features.doc` and `minimal.doc` fixtures (saved by LibreOffice) and the `.doc` samples are the test material.

The parser is split into stages, each a pure function with its own tests: container, FIB, text, formatting, structure (tables, lists), extras (images, links, notes), and the final model build.

## Container

- The file is an OLE compound file, opened with `cfb`. Streams used: `WordDocument` (the FIB, text and formatting pages), `0Table` or `1Table` (which one is given by `FibBase.fWhichTblStm`), and `Data` (pictures). A missing stream the FIB needs gives `corrupt`.

## FIB

- `FibBase` at offset 0 of `WordDocument`: `wIdent` must be `0xA5EC`, otherwise `corrupt`. `nFib` below `0x00C1` (Word 6 and 95) gives `unsupported_version`. `fEncrypted` or `fObfuscated` set gives `encrypted`.
- Then `csw` and `FibRgW97`, `cslw` and `FibRgLw97` (read `ccpText`, `ccpFtn`, `ccpHdd`, `ccpAtn`, `ccpEdn`, `ccpTxbx`, `ccpHdrTxbx`), `cbRgFcLcb` and `FibRgFcLcbBlob` (the `fc`/`lcb` pairs), read by their position for the FIB version found.
- Pairs used: `Clx`, `PlcBteChpx`, `PlcBtePapx`, `Stshf`, `SttbfFfn`, `PlfLst`, `PlfLfo`, `PlcfSed`, `PlcffndRef`, `PlcffndTxt`, `PlcfendRef`, `PlcfendTxt`, `PlcfBkf`, `PlcfBkl`, `SttbfBkmk`. Each pair is an offset and length in the table stream; every read is bounds-checked and a pair pointing outside the stream gives `corrupt`.

## Text

- Character positions (CPs) are positions in the document's text; file positions (FCs) are byte offsets in `WordDocument`. The `Clx` holds `Prc` entries (skipped, except their property modifiers, see Formatting) followed by the `Pcdt`, whose `PlcPcd` maps CP ranges to pieces.
- For each `Pcd`: `fc` with bit 30 (`fCompressed`) set means 8-bit text at byte `(fc & ~0x40000000) / 2`, one byte per character, decoded as Windows-1252 (bytes `0x80` to `0x9F` map to the Windows-1252 table, not Latin-1). Otherwise the text is UTF-16LE at byte `fc`, two bytes per character.
- The document's text is CPs `[0, ccpText)`. Footnote text follows it (`ccpFtn`), then headers (`ccpHdd`), comments, endnotes and text boxes. Only the main text, footnotes and endnotes are used.
- Special characters in the text stream:

| Character | Meaning | Model |
|---|---|---|
| `0x0D` | paragraph end | ends the paragraph |
| `0x07` | cell end, or row end when the paragraph is a table row mark | see Tables |
| `0x0B` | line break | `lineBreak` |
| `0x0C` | page or section break | `pageBreak` block |
| `0x09` | tab | `tab` |
| `0x13`, `0x14`, `0x15` | field begin, separator, end | see Fields |
| `0x01` with `sprmCFSpec` | inline picture | see Images |
| `0x08` with `sprmCFSpec` | floating drawing | skipped in v1 |
| `0x02` with `sprmCFSpec` | auto-numbered footnote or endnote reference | `noteRef` |
| `0x05` with `sprmCFSpec` | comment reference | skipped |
| `0x1E` | non-breaking hyphen | `-` (U+2011) |
| `0x1F` | optional hyphen | dropped |
| `0x28` with `sprmCSymbol` | symbol from a symbol font | the symbol's character code, mapped from Symbol or Wingdings to Unicode where a mapping exists, otherwise dropped |

- A CP is one UTF-16 unit, so a CP is an index into the string a text range decodes to (surrogates and lone surrogates included). A piece that lies outside `WordDocument`, CPs that do not start at 0 or go backwards, and a text range outside the pieces are `corrupt`; an empty piece is allowed.
- Errors are reported in the order of the checks: `wIdent`, `nFib` and the encryption flags are read before the table stream is looked for, so a Word 95 file (which has no table stream) gives `unsupported_version`, not `corrupt`.
- `0x07` ends a paragraph that is in a table (see Tables). Outside a table it ends a paragraph only when it has content, and a stray empty one gives none; without formatting (as in the unit tests of the text stage) every `0x07` is treated as outside a table. `0x0C` ends the paragraph only when it has content, then adds the `pageBreak` block, so a section break after a paragraph mark does not add an empty paragraph. Other control characters below U+0020 are dropped.

## Formatting

- **Character properties**: `PlcBteChpx` lists the FKP pages (512 bytes each, in `WordDocument`) of type `ChpxFkp`. Each page maps FC ranges to a `Chpx` (a `grpprl`, a list of property modifiers called sprms). **Paragraph properties**: `PlcBtePapx` and `PapxFkp` pages map FC ranges (ending at paragraph marks) to `PapxInFkp`: a style index (`istd`) and a `grpprl`.
- Because FKPs are indexed by FC, the text stage keeps, for each piece, its CP-to-FC mapping so properties can be looked up for any CP.
- A piece's `Pcd.prm` can add sprms to all its text (`Prm0` holds one sprm inline, `Prm1` indexes a `Prc` in the `Clx`); they apply after the FKP sprms.
- **Order of application** for a character: paragraph style's character properties → character style (`sprmCIstd`) → the run's sprms → the piece's sprms. For a paragraph: paragraph style (with its base styles, `istdBase`, applied from the root down) → the paragraph's sprms.
- **sprm reading**: the operand size comes from the sprm's `spra` bits (bits 13 to 15): 0 and 1 → 1 byte, 2, 4 and 5 → 2 bytes, 3 → 4 bytes, 7 → 3 bytes, 6 → variable (a size byte first; `sprmTDefTable` and `sprmPChgTabs` have their own size rules). Unknown sprms are skipped by size. A sprm that runs past the end of its `grpprl` ends the list (nothing is thrown). `sprmTDefTable`'s 2-byte size counts itself and the data after it, less one (the operand holds that many bytes after the size). `sprmPChgTabs` starts with a size byte `cb`; when `cb` is 255 the operand is `itbdDelMax`, that many 2-byte positions to delete and as many 2-byte closes, `itbdAddMax`, that many 2-byte positions and as many 1-byte descriptors.
- **Mapping runs to text**: a run's FC range is mapped to CPs through the piece it falls in (1 byte per character in a compressed piece, 2 otherwise), so a run is split at every FC where the character properties change and at every piece boundary. An FC range with no run (a gap) has no properties. A paragraph's properties are those of the `PapxFkp` run that holds its mark (the `0x0D`, `0x07` or `0x0C` that ends it, or its last character when the text ends without one). The paragraph style's character properties apply to every run of the paragraph, so a run's marks depend on both.
- **Prm0**: `isprm` names one sprm, `val` its operand ([MS-DOC] "Prm0"). Only the character sprms the parser reads are mapped: `0x41` `sprmCFRMarkDel`, `0x4D` `sprmCHighlight`, `0x55` `sprmCFBold`, `0x56` `sprmCFItalic`, `0x57` `sprmCFStrike`, `0x5C` `sprmCFVanish`, `0x5E` `sprmCKul`, `0x62` `sprmCIco`, `0x68` `sprmCIss`. Any other `isprm` (including 0) adds nothing. A `Prm1` indexes the `Prc` grpprls of the `Clx`. A piece's sprms only affect characters, never paragraphs.
- **Toggle properties** (bold, italic, strike, hidden, deleted): operand `0` off, `1` on, `0x80` same as the value so far (from the styles), `0x81` the opposite of it.
- Sprms mapped to the model (verify each value against [MS-DOC] when implementing):

| Sprm | Model |
|---|---|
| `sprmCFBold`, `sprmCFItalic`, `sprmCFStrike` | `bold`, `italic`, `strike` |
| `sprmCKul` | `underline` (any style but none) |
| `sprmCIss` | `superscript` (1), `subscript` (2) |
| `sprmCHps` | `fontSizePt` (half-points ÷ 2; 10 pt when no style sets one, as in [MS-DOC]; left out at 11 pt like the other parsers) |
| `sprmCIco`, `sprmCCv` | `color` (`sprmCCv`, a `COLORREF` of red, green, blue and a last byte `0xFF` for auto, wins; ico 0 and cv "auto" mean unset) |
| `sprmCHighlight` | `highlight` (ico table) |
| `sprmCRgFtc0`, `sprmCRgFtc2` | `fontFamily` (index into `SttbfFfn`; `sprmCRgFtc0` is the Latin font, `sprmCRgFtc2` is used when it is absent) |
| `sprmCFVanish` `0x083C`, `sprmCFRMarkDel` `0x0800` | text is dropped (hidden, deleted revision): its characters, tabs and line breaks go, but the paragraph, cell and page-break marks stay. A paragraph whose content was all dropped and whose own mark is hidden or deleted is left out; otherwise it stays as an empty paragraph |
| `sprmPJc` `0x2461`, `sprmPJc80` `0x2403` | `align` (0 left, 1 center, 2 right, 3 to 5 justify); `sprmPJc` wins when both are set |
| `sprmPDxaLeft`, `sprmPDxaRight`, `sprmPDxaLeft1` (and the `80` variants) | `indentLeftMm`, `indentRightMm`, `firstLineMm` (twips) |
| `sprmPDyaBefore`, `sprmPDyaAfter` | `spaceBeforePt`, `spaceAfterPt` (twips ÷ 20) |
| `sprmPDyaLine` | `lineHeight` when the rule is "multiple" (value ÷ 240) |
| `sprmPOutLvl` | heading level (0 to 8 → 1 to 9, 7 to 9 becoming 6; 9 is body text and no heading) |
| `sprmPFPageBreakBefore` | a `pageBreak` block before the paragraph, except at the very start of the document |
| `sprmPIlfo`, `sprmPIlvl` | list (see Lists) |
| `sprmPFInTable`, `sprmPItap`, `sprmPFTtp`, `sprmPFInnerTableCell`, `sprmPFInnerTtp`, `sprmTDefTable`, `sprmTTableHeader` | tables (see Tables) |

- **Styles**: the `STSH` at `Stshf`: `STSHI`, then one `LPStd` per style index. Each `STD` gives `sti` (built-in id: 1 to 9 are Heading 1 to 9), `stk` (paragraph or character), `istdBase`, the name, and its `UPX`s (paragraph: `istd` + `grpprl`; character: `grpprl`). A paragraph is a heading by the shared heading rule (`00-architecture.md`) applied to the names of its style and the styles it is based on and to `sprmPOutLvl`. The `STSHI` is `cbStshi` (2 bytes), then the `STSHI` itself: `cstd`, `cbSTDBaseInFile`, and more. Each `LPStd` is `cbStd` (2 bytes; 0 is an empty slot) and the `STD`: `cbSTDBaseInFile` bytes of `STDFixed` (`sti` in the low 12 bits of the first word; `stk` in the low 4 bits and `istdBase` in the high 12 bits of the second; `cupx` in the low 4 bits of the third; `0x0FFF` means no base), then the name as an `Xstz` (a 2-byte length, the UTF-16 characters, a 2-byte terminator), then `cupx` UPXs, each a 2-byte size and its bytes, padded to an even length. A paragraph style's first UPX is the paragraph one (`istd`, then the `grpprl`) and its second the character one; a character style has only the character one. A style with no stored name takes the built-in one for its `sti` (0 Normal, 1 to 9 Heading 1 to 9, 62 Title). A damaged style is left empty instead of failing the file, and a loop in the `istdBase` chain is cut where it closes.
- **Fonts**: `SttbfFfn` is a 2-byte count, a 2-byte `cbExtra` (skipped), then the `FFN`s in index order. Each `FFN` is `cbFfnM1` (its size minus one), 39 bytes of flags, weight, charset, panose and font signature, then the name in UTF-16 up to a terminator. A damaged entry ends the list.
- **Page**: the first section's `SEPX` (from `PlcfSed`'s first `Sed.fcSepx`): `sprmSXaPage`, `sprmSYaPage`, `sprmSDxaLeft`, `sprmSDxaRight`, `sprmSDyaTop`, `sprmSDyaBottom` (twips). Missing values use Word's defaults (Letter, 1 inch top and bottom, 1.25 inch left and right). A negative top or bottom margin counts as its absolute value. A file with no `PlcfSed` has no page; a `Sed` with no `SEPX` (`fcSepx` `0xFFFFFFFF`) gets all the defaults.

## Fields

- `0x13` instruction `0x14` result `0x15`, possibly nested. The parser keeps a stack. Only the result (between the separator and the end) is shown; a field with no separator shows nothing.
- A character is shown only when every open field is in its result; otherwise it belongs to the instruction of the innermost open field still in its instruction (so a field nested in an instruction, like `REF`, adds its result to it). A second separator, an end with no begin and a begin with no end are dropped. A link covers the result of its field; inside nested hyperlinks the innermost wins. Field data (`0x01` in an instruction) is dropped with the instruction, and a field spanning paragraphs gives one link per paragraph.
- `HYPERLINK "url"` instructions turn the result into a `link`; the `\l "bookmark"` switch makes it `#bookmark` (`url \l "bookmark"` gives `url#bookmark`); the `\o` and `\t` switches take an argument that is ignored; quoted text reads `\\` and `\"` as escapes. A HYPERLINK with no target is not a link. `PAGEREF`, `REF`, `TOC` and the rest show their result as text.

## Tables

- A paragraph with `sprmPFInTable` (depth `sprmPItap`, 1 when absent; a `sprmPItap` without `sprmPFInTable` also counts) is in a table. Depths are cut to 15, Word's limit, so a bad `sprmPItap` cannot recurse without end. A paragraph ends a cell when its mark is `0x07`, or when it has `sprmPFInnerTableCell` (nested tables end their cells with `0x0D` plus that flag). The row ends at a paragraph that is a table row mark: `sprmPFTtp`, or `sprmPFInnerTtp` for nested depths (either flag counts at any depth, and a row mark is at least at depth 1). That paragraph's `sprmTDefTable` gives the cell boundaries (`rgdxaCenter`, so widths in twips) and per-cell `TC80` flags, and `sprmTTableHeader` marks a header row.
- The `TC80` flags are the low bits of `tcgrf`: bit 0 `fFirstMerged`, bit 1 `fMerged` (old-style horizontal merges), bit 5 `fVertMerge`, bit 6 `fVertRestart`. A cell with `fVertRestart` starts a vertical merge; one with only `fVertMerge` continues the cell above it. A `TC80` list cut short leaves the remaining cells unmerged; an operand too short for its boundaries gives no definition.
- The row-end paragraph's own content is never output. Its text is dropped, and it adds no paragraph to a cell.
- Every cell keeps at least one paragraph: an empty cell has one empty paragraph. A cell's last paragraph is kept even when its text and mark are hidden or deleted (it becomes an empty paragraph), since dropping it would drop the cell.
- Column spans come from the `rgdxaCenter` boundaries of all rows (the column grid rule in `00-architecture.md`, with each row's left edge `rgdxaCenter[0]`); the old-style `fFirstMerged`/`fMerged` flags are also honoured: a merged cell is folded into the first one, and any content it holds is appended to it. Vertical merges become `rowSpan`; merged-away cells are omitted, and a continuing cell with no restart above it (in its first column) is an ordinary cell. A row with no readable definition gets half-inch columns, and cells beyond the definition's count likewise. Column widths in millimetres come from the grid. Consecutive rows at the same depth form one table; the format has nothing that separates two tables directly after each other, so they are one table.
- Nested tables (depth above 1) are built as tables inside the cell that holds them, in order with that cell's paragraphs. If the nesting is inconsistent (a nested table whose last row has no row mark), the inner paragraphs are flattened into paragraphs of the outer cell. A depth-1 table cut short (no row mark for its last row) is flattened the same way into the body, so no text is lost.

## Lists

- `sprmPIlfo` (1-based index into `PlfLfo`) and `sprmPIlvl` (level 0 to 8) put a paragraph in a list. `LFO.lsid` finds the `LSTF` in `PlfLst`; the `LVL` structures follow the `PlfLst` in the table stream, nine per list (one for "simple" lists). An `LFOLVL` in the `LFO`'s `LFOData` (after a 4-byte `cp`) is an `iStartAt`, then a 4-byte field with `ilvl` in the low 4 bits, `fStartAt` (bit 4) and `fFormatting` (bit 5); with `fFormatting` a whole `LVL` follows and replaces that level.
- Each `LVL` gives `nfc` (number format: 0 decimal, 1 upper Roman, 2 lower Roman, 3 upper letter, 4 lower letter, 22 decimal with leading zero, 23 bullet, 255 none), `iStartAt`, and `xst`, the marker template, where characters 0 to 8 are placeholders for the current number of that level.
- The parser keeps a counter per list and level: a paragraph increments its level's counter (the first time it is the level's start value, `iStartAt` or the `LFOLVL` start) and resets the deeper levels; the marker is `xst` with each placeholder replaced by that level's number in its level's format (a level not counted yet shows its start value). Bullet markers that use a Symbol or Wingdings code point are mapped to "•", "◦" or "▪"; an empty bullet marker is "•". `nfc` 255 gives an empty marker. `ixchFollow` (tab, space or nothing after the marker) adds nothing to the marker text.
- Counters are kept per list, so two `LFO`s of the same `lsid` share them. LibreOffice writes a one-paragraph copy of a list for a first item whose number restarts and uses the original for the items after it, so a list first used right after a copy of itself (the same `nfc`, `xst`, start, restart limit and indents on every level) that has numbered exactly one paragraph continues that copy's counters. Separate lists that merely look the same, such as two numbered lists in a Word file, keep their own counters. An `LFO` with an `LFOLVL` start value restarts that level at that value the first time a paragraph uses the `LFO`.
- `ilvlRestartLim`, when above 0 and below the level's own index, makes the level restart only after levels 0 to `ilvlRestartLim - 1`; otherwise a level restarts after any shallower one. A simple list (one level) uses that level for every `ilvl`. An `ilfo` with no `LFO` or list, an `ilvl` above 8, and a paragraph that is gone (all its text and its mark hidden) are not counted.
- A paragraph's indents are applied in this order: its style, the list level's `grpprlPapx`, the paragraph's own sprms. A `PlfLst` or `PlfLfo` the stream cuts short keeps the lists and `LFO`s read before the cut.
- `ordered` is false for bullets (`nfc` 23 or 255), true otherwise.

## Images

- An inline picture is a `0x01` character with `sprmCFSpec`; its `sprmCPicLocation` operand is an offset into the `Data` stream, where a `PICFAndOfficeArtData` starts: a `PICF` (`lcb`, `cbHeader`, `mfpf.mm`, `dxaGoal`, `dyaGoal`, `mx`, `my`), the picture name when `mm` is `0x0066`, then an OfficeArt `OfficeArtInlineSpContainer`: a shape container followed by `OfficeArtFBSE` records holding the BLIP.
- BLIP record types: `0xF01D` JPEG, `0xF02A` JPEG (CMYK), `0xF01E` PNG, `0xF01F` DIB (made into a BMP by adding a file header), `0xF01A` EMF, `0xF01B` WMF, `0xF029` TIFF. Bitmaps skip the record header, one or two 16-byte UIDs (two when the instance is the "two UIDs" value) and the tag byte. EMF, WMF and TIFF become a placeholder of the right size.
- Display size: `dxaGoal × mx / 1000` by `dyaGoal × my / 1000` twips, converted to pixels.
- Finding the picture: the `PICF` is read at `sprmCPicLocation`; a `PICF` with `mm` 0 (the field data of a link, for instance) is not a picture and gives none. The records after the header (and after the name when `mm` is `0x0066`) are walked within the `PICF`'s `lcb` (the end of the stream when `lcb` is smaller than `cbHeader` or runs past it): a record with version `0xF` is stepped into, an `OfficeArtFBSE` is stepped into after its 36 fixed bytes and its name, and the first BLIP found wins. A record that runs past its container ends the walk, so a truncated picture has no BLIP.
- An instance value with its low bit set is a "two UIDs" value (`0x6E1`, `0x46B`, `0x6E3`, `0x7A9` and the metafile and TIFF ones), so the bitmap data starts after 17 or 33 bytes.
- Placeholders: everything that cannot be shown is an image without `src`, never an error: no `Data` stream, a location whose `PICF` does not fit in the stream (0 by 0 px, since there is no size to read), an `mm` other than `0x0064` and `0x0066` (a legacy metafile picture), a record that does not parse, a bitmap with no data, a DIB too short for a bitmap header, and EMF, WMF and TIFF BLIPs. A placeholder takes the size of the `PICF` when it can be read.
- In the text: a `0x01` in shown text is a picture only when `sprmCFSpec` is set and `sprmCFData` is not; the `0x01` of a field instruction never reaches this step. A picture whose character is hidden or deleted is dropped like other text. A picture in a link's result stays in the link.
- Floating pictures and shapes (`0x08`, OfficeArt in the table stream) are not read in v1.

## Notes and bookmarks

- `PlcffndRef` gives the CP of each footnote reference and `PlcffndTxt` the CP ranges of their text inside the footnote part (starting at `ccpText`); endnotes likewise, in the endnote part (starting at `ccpText + ccpFtn + ccpHdd + ccpAtn`, `ccpEdn` long). Each becomes a `Note` and a `noteRef` at the reference.
- The reference PLC is n + 1 CPs then n `FRD`s (2 bytes, `nAuto` first); the text PLC is n + 2 CPs, note i being `[cp[i], cp[i + 1])` and the last entry a guard. The count is the smaller the two tables allow. A note whose reference is not in the main text, or whose range is not inside its part, is left out together with its reference, so no link points nowhere.
- Labels: footnotes "1", "2"…, endnotes "i", "ii"…, counted in each kind's reference order. An `FRD` with `nAuto` 0 is a custom mark: the character at the reference CP is the label, and that character (not a `0x02`) is what the `noteRef` replaces. A custom mark does not use up a number, and one with nothing printable in it is numbered instead. Note ids are "fn1", "fn2"… and "en1", "en2"…
- The model's `notes` hold the footnotes first, then the endnotes. A note's text is parsed with the code of the main text (paragraphs, formatting, tables, lists, pictures), over its own CPs so formatting is found by CP. The note's own mark is dropped: a leading `0x02`, or for a custom mark the leading label text. Whitespace at the start of the first text run is trimmed (Word puts a space after the mark). References and bookmarks of the main text are not applied inside notes.
- `SttbfBkmk` is an extended string table (`0xFFFF`, a count, `cbExtra`, then each name as a 2-byte length and UTF-16 characters, then `cbExtra` bytes) and `PlcfBkf` is n + 1 CPs then n `BKF`s; bookmark i has name i and starts at CP i. A table that is not extended, a name that runs past the table, an empty name and a repeated name (the first stays) are skipped, and the bookmarks are sorted by CP. `PlcfBkl` (the ends) is not needed.
- Each bookmark that starts in the main text becomes an `anchor` inline with the bookmark's name as its id, so `#bookmark` links work. It goes in front of the character at its CP, or, when that CP is in text that is not shown (a field instruction), in front of the next shown character; it stays even when that text is hidden, and a paragraph holding only an anchor stays. Anchors and note references are never inside a link (their element cannot nest in one), so a link that one falls inside is split around it.

- Streams: `WordDocument`, `1Table` (`fWhichTblStm` is 1), `Data`. `nFib` is `0x0101`, `csw` 14, `cslw` 22, `cbRgFcLcb` 136 (`0x88`).
- `FibRgLw97`: `ccpText` 862, `ccpFtn` 51, `ccpHdd` 81, the rest 0. The piece table covers CPs 0 to 995, one more than their sum (the document's final paragraph mark).
- `FibRgFcLcb97` pairs by index (fc, lcb): 1 `Stshf` (0, 2604), 2 `PlcffndRef` (2604, 10), 3 `PlcffndTxt` (2614, 12), 6 `PlcfSed` (2626, 20), 11 `PlcfHdd` (2646, 56), 12 `PlcfBteChpx` (2702, 12), 13 `PlcfBtePapx` (2714, 52), 15 `SttbfFfn` (5385, 1064), 16 `PlcfFldMom` (2766, 22), 21 to 23 `SttbfBkmk`, `PlcfBkf`, `PlcfBkl`, 33 `Clx` (5364, 21), 46 and 47 `PlcfendRef`, `PlcfendTxt` (empty), 73 `PlfLst` (2828, 142), 74 `PlfLfo` (5208, 104). - `STSHI`: 60 styles, `cbSTDBaseInFile` 10. Style 0 "Normal", 1 to 6 "Heading 1" to "Heading 6" (`sti` 1 to 6), 42 "Title" (`sti` 62).
- Character sprms present: `sprmCFBold` `0x0835`, `sprmCFItalic` `0x0836`, `sprmCFStrike` `0x0837`, `sprmCKul` `0x2A3E`, `sprmCIco` `0x2A42`, `sprmCCv` `0x6870`, `sprmCHighlight` `0x2A0C`, `sprmCIss` `0x2A48`, `sprmCHps` `0x4A43`, `sprmCRgFtc0` `0x4A4F` (with `0x4A50`, `0x4A51` for the other script ranges), `sprmCIstd` `0x4A30`, `sprmCFSpec` `0x0855`, `sprmCPicLocation` `0x6A03`, `sprmCFData` `0x0806`, `sprmCFFldVanish` `0x0802`.
- Paragraph sprms present: `sprmPJc80` `0x2403`, `sprmPJc` `0x2461`, `sprmPFPageBreakBefore` `0x2407`, `sprmPDyaBefore` `0xA413`, `sprmPDyaAfter` `0xA414`, `sprmPIlvl` `0x260A`, `sprmPIlfo` `0x460B`, `sprmPFInTable` `0x2416`, `sprmPFTtp` `0x2417`, `sprmPItap` `0x6649`, `sprmTDefTable` `0xD608`, `sprmTTableHeader` `0x3404`. List paragraphs carry no indent sprms: their indents come from the list level's `grpprlPapx`.
- The first `SEPX` (at `Sed.fcSepx` 7680): `sprmSXaPage` `0xB01F` 11906, `sprmSYaPage` `0xB020` 16838, `sprmSDxaLeft` `0xB021` 1440, `sprmSDxaRight` `0xB022` 1440, `sprmSDyaTop` `0x9023` 1440, `sprmSDyaBottom` `0x9024` 1440 (A4, 2.54 cm margins).
- FKP layout as read: a 512-byte page whose last byte is `crun`; a `ChpxFkp` has `crun + 1` FCs then `crun` one-byte offsets (×2, 0 means no properties) to `cb` + `grpprl`; a `PapxFkp` has `crun + 1` FCs then `crun` 13-byte `BxPap` entries whose first byte is the offset (×2) to a `PapxInFkp`: `cb` (if 0, the next byte `cb'` and size `2 × cb'`, else size `2 × cb − 1`), then `istd` (2 bytes) and the `grpprl`. `PlcBteChpx`/`PlcBtePapx` hold `n + 1` FCs then `n` 4-byte page numbers (low 22 bits; the page is at `pn × 512` in `WordDocument`).
- Formatting as parsed: the Normal style of `features.doc` sets Calibri 11 pt (so every run carries `fontFamily: "Calibri"` and no size), while that of `minimal.doc` sets Times New Roman 10 pt. The 53 character runs and 55 paragraph runs are contiguous from `0x800` and cover all the main text. Several `Sprm`s come in old and new versions (`sprmPJc80` `0x2403` and `sprmPJc` `0x2461` both appear on the same paragraphs).
- Lists: `PlfLst` holds `cLst` (2 bytes, 5 here) then 28-byte `LSTF`s (`lsid` first; `fSimpleList` is bit 0 of byte 26). The `LVL`s follow the `PlfLst` directly (here they end exactly where `PlfLfo` starts, at 5208): nine per list (one for a simple list), each a 28-byte `LVLF` (`iStartAt` 4 bytes, `nfc` 1, flags 1, `rgbxchNums` 9, `ixchFollow` 1, `dxaIndentSav` 4, unused 4, `cbGrpprlChpx` 1 at byte 24, `cbGrpprlPapx` 1 at byte 25, `ilvlRestartLim` 1, `grfhic` 1), then the `grpprlPapx`, then the `grpprlChpx`, then `xst` (2-byte count + UTF-16). The numbered list (`lsid` 4) has level 0 `nfc` 0 with `xst` "\u0000." and level 1 `nfc` 4 with `xst` "\u0001)"; the bullet list (`lsid` 5) has level 0 `xst` "\uF0B7" (Symbol bullet, private use, which looks empty when printed) and level 1 "◦". `lsid` 1 and 2 are copies of them (identical levels), `lsid` 3 has nine `nfc` 255 levels. The paragraphs use the copies for the rest of each list: the first numbered item has `ilfo` 4, the nested lettered and the second numbered item `ilfo` 1 (levels 1 and 0), the first bullet `ilfo` 5 and the nested bullet `ilfo` 2, which is why identical lists share counters. No `LFO` has an `LFOLVL`. Level indents come from `grpprlPapx`: `sprmPDxaLeft` 720 or 1440 and `sprmPDxaLeft1` −360. `PlfLfo` holds `lfoMac` (4 bytes, 5 here), then 16-byte `LFO`s (`lsid` first, `clfolvl` at byte 12), then the `LFOData` of each.
- Pictures: the two inline pictures are `0x01` characters at CPs 806 and 808 with `sprmCPicLocation` 172 and 10388. Their `PICF` has `cbHeader` 68, `mfpf.mm` `0x64`, `dxaGoal`/`dyaGoal` 3600 × 1800 and 4800 × 3000 twips, `mx`/`my` 1000. After the header come the OfficeArt records: an `OfficeArtSpContainer` (`0xF004`, a container, version `0xF`, so step into it rather than over it), then `OfficeArtFBSE` (`0xF007`): 36 fixed bytes with the name length at byte 33, the name, then the BLIP record: PNG `0xF01E` instance `0x6E0` and JPEG `0xF01D` instance `0x46A`, each with one 16-byte UID and a tag byte before the image data (instances `0x6E1`, `0x46B` and the other "two UID" values have two UIDs). The hyperlink's field-data `0x01` (in the field instruction) also has a `sprmCPicLocation`, 0: its `PICF` has `mm` 0 and `lcb` 171 and is not a picture. Many other characters carry `sprmCPicLocation` 0 too; only a `0x01` in shown text with `sprmCFSpec` is a picture.
- Footnotes: `PlcffndRef` has one reference at CP 542 (the `0x02` character) with an `FRD` of 1 (auto-numbered). `PlcffndTxt` holds CPs 0, 50 and 51, relative to the start of the footnote part (`ccpText`): the note is `[0, 50)`, and the last entry is a guard for the part's final paragraph mark.
- Tables: each row-end paragraph (CPs 679, 700, 716 and 740 for the four rows) carries `sprmTDefTable`. Its operand is a 2-byte `cb` followed by `cb − 1` bytes: `itcMac` (1 byte), `rgdxaCenter` (`itcMac + 1` signed 2-byte values) and `itcMac` 20-byte `TC80`s whose first 2 bytes are `tcgrf`. Rows 1 to 3 have boundaries 5, 3013, 6022, 9031; row 4 has 5, 6022, 9031 (its first cell spans two grid columns). The table's paragraphs have `sprmPFInTable` and `sprmPItap` 1, and the row-end paragraph also `sprmPFTtp`. An empty paragraph follows the table. "Delhi" has `tcgrf` bits 5 (`fVertMerge`) and 6 (`fVertRestart`) set; the cell below it bit 5 only. The first row also has `sprmTTableHeader`.
